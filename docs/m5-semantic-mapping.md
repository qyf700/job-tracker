# M5.1：本地字段映射与 Moka 控件回读

## 参考项目与取舍

实际下载并阅读 OpenJobAutofill 的 content.js、background.js，ResumePilot 的 complex-controls.js、autofill.js；版本、文件及 MIT 许可全文见连接器 THIRD_PARTY_NOTICES.md。代码采用本项目独立实现，没有加载上游执行环境、示例个人资料、账号配置或 AI 服务。

OpenJobAutofill 将资料目录、页面字段、分类约束、匹配理由和执行计划分开。我们采用目录/分组/别名/来源/缺项的设计；没有采用弱匹配直接覆盖现有值，也没有把真实资料交给模型。ResumePilot 的控件探测限制候选范围，并在选择后回读；我们将该思路缩小为实际核验的 Moka SD 下拉控件，等待唯一候选并核对显示值，不把弹层关闭当作成功。

## 已实现流程

1. fields.mjs 从已经确认的冻结快照派生标准字段目录。包含空项，才能指出缺资料；每个取值带 profile_version/job_answer、资料版本和源路径。岗位答案优先，保持快照原文，不根据 JD 或官网现有内容猜答案。
2. moka-adapter.mjs 扫描标签、章节、控件类型、必填标记、重复序号、禁用和占用布尔值。不回传官网已有字段的实际值，不把教育背景倒灌进工具。
3. mapping.mjs 进行同分组的精确标签或已核验别名匹配，如“联系电话→phone”“意向工作城市→expectedCities”。现有值保留；某段官网经历已有部分内容时，整段空字段也转人工核对，避免按序号混入另一段经历。空资料、同名歧义、类型不符、经历数量差异分别提示；推荐人、家庭、凭据、协议、验证码不参与普通填表。规则等级不是模型置信概率。
4. 扩展展示目标岗位、简历哈希、冻结版本、各字段状态/来源/实际冻结值；没有候选时不会消耗单次填写授权。未处理登录/验证码/协议时可只读预览，禁止写入。
5. 预览绑定无个人值的结构指纹。执行前及写入期间再次检查结构，页面变更要求重新确认。字段实际值变化不进入指纹，写前仍保留新增的官网已有值。
6. SD 下拉只搜当前控件内部唯一、可见、未禁用的精确选项，有限等待并回读实际显示值。日期作为整体检查：已有任何部分且与目标不一致时整组保留，避免拼接出混合日期。学校/专业自动补全文本仍要求本人确认选项；不声称输入文字就完成选择。

## 保留的约束

资料版本、冻结快照、任务状态机、设备配对、租约、操作单次授权与结果日志不变，没有新增或改写数据库表。所有写入只针对有效租约的冻结材料；未知结果不自动重做，真实文件只在本人确认后传给官网；没有最终提交命令，仍停在最终确认前。

首个验证站点仍为知乎/Moka 已核验推荐算法职位。通用字段映射可复用，但其他站点的 DOM/控件/上传仍需独立核验，不能据此宣称全网兼容。

## 验证与限制

现场只读核验了登录后真实页面的18个字段组，含两段教育经历。保存在 tests/fixtures/zhihu-moka-schema.json 的是公开标签、控件类型与占用/禁用布尔值，不包含姓名、电话、学校名称、专业、附件名、Cookie 或官网实际填写内容。使用空资料映射时，三个必填缺口（是否实习、招聘来源、期望城市）被准确列出，已有毕业时间和教育经历全部保留。

单元测试覆盖分组/别名、缺项、他人资料阻断、经历数量、结构变化、真实脱敏结构、别名执行、异步下拉回读和重复候选拒绝。Worker/D1/R2 集成测试继续覆盖冻结数据、账号隔离、任务领取及单次操作/确认约束。测试中的 DOM、浏览器 API 桩和人工候选资料只在隔离测试使用，不构造生产岗位或投递结果。

用户尚未安装/配对 Chrome 扩展，工具内尚无完整真实材料。因此，本次真实站点验证是结构与映射只读验收；完整扩展填写、上传完成、学校/专业候选选择仍需本人材料与 Chrome 联调。没有向知乎上传测试简历，也没有提交申请。
