# 求职工作台 v1 产品需求

v1 面向需要持续收集秋招和实习岗位、手动在官网申请并管理进度的求职者。首页回答「哪些公司近期还有开放岗位」，台账回答「我投过哪些公司、对应哪个岗位、下一步是什么」。

## 功能与现状

| 功能 | 现状及缺口 | v1 验收条件 |
| --- | --- | --- |
| 官网岗位采集 | 已有知乎/Moka 来源、手动同步、详情、搜索和分页。公司筛选写死 | 按已接入官网同步真实列表及详情。每条显示原文入口和核验时间；失败保留上次成功结果 |
| 企业在招情况 | 缺少按公司汇总，翻页后的数量不能代表整个目录 | 全目录按公司统计已核验开放和过期岗位，可点击公司查看职位。超过 24 小时的开放记录显示待核验 |
| 岗位收藏 | 官网岗位可保存到台账，重复保存幂等 | 保存后出现待投递记录，收藏不会产生投递时间 |
| 投递台账 | 已有手动添加、更新状态、行动、截止日期和归档。旧规则可能把直接结束的岗位视为已投 | 保留待投递、已投递、流程中、Offer、未通过、已撤回、已结束。待投岗位直接结束时不新增投递时间 |
| 已投企业 | 缺少企业历史汇总，只按当前状态筛选会漏掉进入面试的岗位 | 根据台账已有投递时间分组。点击公司精确筛选，可看到岗位当前状态和跟进事项 |
| 面试与待办 | 已有多轮记录和日历 | 从台账仍能查看和管理，面试记录关联具体申请 |
| 官网执行 | 已有准备单和连接器，真实端到端尚未验收 | v1 暂停填表和上传，移除主要入口，后端拒绝新的执行授权 |

## 数据口径

- 当前正式来源只有知乎/Moka。公司统计以已接入目录为范围，缺少来源的企业不作招聘状态判断。
- 开放取自官网详情与核验时间。秋招、实习批次、毕业届别和截止日期以官网证据为准。无明确依据时显示未知。
- 已投企业来自用户手动记录，属于个人台账。过往记录沿用保存的投递时间，发现历史误记可后续补充更正能力。
- 收藏和跟进需要账号隔离。测试数据仅落隔离环境。

## 实施与发布

第一批补齐企业在招汇总、已投企业视图、关闭未投岗位的状态语义，以及官网执行暂停。发布前验证真实知乎采集、分页与筛选、隔离台账状态和前端可用性。上线后从工作台发起官网同步，并返回实际结果。

新增企业来源放到下一批。每家先核验公开招聘入口、职位详情、分页和开放状态证据，完成采集回归后再加入目录。跨企业同名归并、历史投递时间更正和周期性刷新列入后续迭代。
