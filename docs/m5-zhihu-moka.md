## 用户流程

1. 下载安装 v0.3.0，配对本人设备，在同一浏览器保持工作台登录并打开。
2. 用本人真实简历和资料生成冻结快照并确认，领取任务打开对应官网。
3. 本人处理官网登录、验证码和官网协议。扩展只报告等待，不勾选协议、不获取验证码或登录凭据。
4. 重新核对目标页，读取填写与上传预览：岗位、官网地址、原件名称/大小/哈希、资料版本和具体字段值。
5. 勾选材料传输确认，点击“上传此冻结简历原件”。此时文件会立即交给真实官网控件，可能触发官网解析，不是仅在工具内准备文件。
6. 等待官网显示文件名并完成解析；再次预览，确认后填写能精确匹配的空白字段。官网已有值不会覆盖。学校、专业的输入不等于官网选项已选中，必须本人核对。找不到精确选项、结构变化或重复字段不明确时停止该字段，显示手动处理。
7. 本人逐项核对必填项、选项和附件，勾选复核后进入“等待最终确认”。扩展没有最终提交命令；本人在官网再次确认并点击“预览并提交”。本版本不读取回执、不标记已投递。

## 授权、存储与状态

新增 browser_actions：ID、本人/设备/租约/任务/快照绑定、fill 或 upload 类型、状态及时间和结果摘要。task_id + kind 唯一；操作开始即持久化，丢失响应也不能自动重做。同一任务每种操作只能授权一次；需要重做时先核对官网，重新确认新的材料快照。数据库触发器禁止删除、改写身份或覆盖最终结果。

设备证明、租约证明、冻结材料的权限沿用 M4。操作还要求当前任务版本、规范化官网地址、冻结快照哈希、明确确认，并重新核验官方岗位仍开放。授权仅允许立即执行（最长20秒且不超过租约截止）；扩展每次写入前重新检查目标页、登录/验证码/协议门槛。

扩展会在服务端授权之前保存本机操作标记。网络结果未知或进程中断时不自动重新填写/上传；只有结果回传可幂等重试。材料值、文件字节只在执行内存中使用，不存入扩展长期存储，不把官网正文、Cookie、验证码或字段值写进操作日志。

新增状态：adapter_running（已授权待核对结果）、needs_manual_fields（请本人核对字段/附件）、awaiting_final_confirmation（待最终确认，尚未投递）。未知结果进入 needs_review。发生过官网操作后，释放租约进入人工核对，不直接自动排队。

上传三重核验：冻结 R2 元数据、扩展字节 SHA-256/大小、官网脚本再次核对 SHA-256/大小/PDF头。只给精确的 `input#resumeKey[type=file][name=resumeKey]` 赋值并发送 change，调用真实官网原有上传逻辑；不伪造上传 URL 或 Cookie。返回 upload_dispatched 只表示事件已触发，不能代表服务端上传成功或申请已投递。

## API

均为 `/api/browser-connector` 下的 POST，需要 Sites 身份和设备证明，严格 JSON 体，租约证明不出现在 URL。

| 路径 | 输入与用途 |
| --- | --- |
| /device/adapter-plan | 租约证明；只读冻结映射、哈希、当前任务与既有操作 |
| /device/adapter-start | 证明、actionId、version、kind、snapshotHash、pageUrl、acknowledged=true；单次竞争授权 |
| /device/adapter-result | 证明、actionId、outcome；只接受 fill_observed/upload_dispatched/uncertain，无自由正文 |
| /device/adapter-review | 证明、version、acknowledged=true；用户核对后进入最终确认，不提交 |

## 登录后核验修正 v0.3.1

实际登录后核验了表单和下拉节点：选项为当前 sd-Dropdown-container 内的 sd-Menu-content-item；不从整个页面搜同名选项。官网已有简历可能以不带扩展名的姓名按钮显示，因此上传预检同时识别 file_upload-btn 的文本，除“上传简历”外均保留并拒绝自动覆盖；预检在服务端授权前执行。已有教育经历及禁用的毕业时间保留，缺少工具资料时不会从官网倒推或自动生成答案。

资料里的是否实习、期望城市、招聘来源可日后在小工具填写；岗位专属答案覆盖默认答案时仍须预览确认。当前未提供真实原件和完整资料，不进行实际填表/上传。此核验不等于所有公司通用适配通过。
